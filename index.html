The synapse that never fills up

A fixed-size synaptic weight matrix, written by co-activation and read by a cue, can hold a sequence of unbounded length without allocating a slot per token — and it forgets through interference between stored associations, not by running out of room.

The substrate

This is a memory. It is already remembering.

On the right is a single synaptic weight matrix S, sized 32 × 32. It started empty. We streamed a short sequence of (name → digit) pairs into it. Each pair was written with one rule — the same rule a Hebbian synapse follows: units that fire together wire together.

write S ← λ·S + k·vᵀ outer product of key k and value v
read r = Sᵀq probe the matrix with a cue q

The grid never changes shape. It is the same size whether you store one pair or a thousand. Watch it fill with structure as you scrub through the writes.

Claim 1 · unbounded sequence, fixed state

Add more memories. The state does not grow.

A Transformer answers a query by comparing it against a stored key for every previous token. That store — the KV cache — grows with the sequence. Drop the softmax and the sum reassociates into a single fixed matrix S = Σ kᵢvᵢᵀ. That is the linear-attention / fast-weight view.

Claim 2 · it forgets, but not by deleting

Read one memory back. See what leaks in.

Nothing is ever erased. So why does recall fail as you store more? Probe S with a stored key kⱼ and the read decomposes exactly:

r = vj(kj·kj) + Σi≠j vi(ki·kj)

The first term is the answer you want. The highlighted sum is crosstalk — every other memory leaking in, weighted by how much its key overlaps your cue. Pick a cue and a store size and watch the two compete.

The BDH connection

Where this lives in Dragon Hatchling

Everything above is the mechanism at the heart of Pathway's Dragon Hatchling (BDH). BDH reformulates attention as synaptic memory: the fast weight S is not a cache bolted on beside the model — it is the model's working memory, updated as it reads. BDH-CQ relates its contextual memory to this same fast-weight / linear-attention view of association.

One BDH detail changes the picture here, and you can test it. BDH reports roughly 5% of neurons active, and those activations are non-negative (ReLU). Non-negativity removes sign cancellation, so crosstalk that used to average out now always adds. Sparsity is what keeps that survivable. Flip the key regime and measure it.

Honesty note. This is a toy associative memory with random keys, not a BDH checkpoint. BDH learns its keys, so real learned sparse codes are closer to orthogonal and store more than random ones do here. This substrate demonstrates the mechanism and its scaling law; it does not measure any Pathway model. No BDH checkpoint was run for anything on this page.

Say it back

In one breath

A synapse-style memory writes each association as an outer product into one fixed matrix, so a sequence of any length costs the same state. Reading it back is a weighted vote: the cue's own memory versus the crosstalk of every other memory that overlaps it. It never runs out of slots — it degrades as overlap accumulates. Sparse, non-negative codes keep that overlap small, which is why BDH can turn attention into synaptic memory and still reason.

One thing not to walk away believing

Within-session synaptic memory is not the same as durable, cross-session learning. This matrix resets when the context ends. Consolidating useful fast state into slow trained weights is an open problem BDH explicitly frames — not something this mechanism solves on its own.

What's live, what's precomputed, what's a limit

  • Live: every matrix, bar, curve, and number on this page is computed in your browser from src/engine.js at the seed shown. Change a control, the math reruns.
  • Precomputed: nothing. The recall-vs-load curves average a handful of seeds on the fly; on a slow device they may take a beat.
  • Stated limits: d_k, d_v and store sizes are capped small so state stays visible. Keys are random, not learned. The BDH connection is at the level of mechanism and published equations, not a reproduction.
  • Reproduce the numbers: node scripts/verify.mjs prints every figure this page and the README rely on, deterministically at seed 42.
